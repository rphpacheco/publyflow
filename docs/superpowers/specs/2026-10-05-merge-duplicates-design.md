# Merge duplicate companies and contacts (+ company aliases)

Date: 2026-10-05. Status: approved design (user, 2026-10-05), pending written-spec review.
Origin: TAREFA 1c. Inbox conversion creates companies/contacts from AI guesses, so duplicates appear ("Bella" vs "Bella Cosméticos"). Companies & Contacts pages (2026-10-05) deferred merging to this spec.

## 1. Decisions

| # | Decision |
|---|---|
| D1 | Scope: merge **companies** and **contacts**. Brands are out (they can already be renamed/moved). |
| D2 | Field conflicts: the record that **stays** wins; its **empty** fields are filled from the duplicate (contacts: email, phone, instagramHandle, companyId; companies: only `name`, which stays). A preview shows the result before confirming. |
| D3 | **Aliases for companies only.** Inbox conversion looks companies up by name; contacts are never looked up by name (`CommercialInquiryService` always creates a contact unless an explicit id is given), so contact aliases would be dead data. Merging a company stores the duplicate's name as an alias of the remaining company; conversion matches name **or** alias. |
| D4 | **No undo.** The confirmation shows the impact and "Esta ação não pode ser desfeita."; an internal record is kept as a domain event (`company.merged` / `contact.merged`, no handler — the drain marks it done and the row stays). |
| D5 | Entry point: "Mesclar em…" button on the **duplicate's** detail page → dialog: choose the record that stays, preview, confirm → navigate to the record that stayed. |
| D6 | Execution: one transaction in the service (approach 1): lock both rows in id order, re-point references, fill blanks, aliases, delete duplicate, append event. A preview endpoint computes the same impact without writing. |
| D7 | Access: OWNER/MANAGER only (CREATOR → 403), like the rest of the CRM. |
| D8 | One migration (0023) creating `company_aliases` — schema only, no data change. Deploy order: apply 0023 in production, then push. |

## 2. Data

`company_aliases` (migration 0023, generated by drizzle-kit, RLS appended by hand like 0017/0021):
- `id uuid pk`, `organization_id uuid not null → organizations (cascade)`, `company_id uuid not null → companies (cascade)`, `name text not null`, `created_at timestamptz not null default now()`.
- Unique index on `(organization_id, lower(trim(name)))`.
- `alter table company_aliases enable row level security;` + `create policy org_isolation_company_aliases on company_aliases …` (same form as `org_isolation_proposal_approvals`).
- Add `company_aliases` to `DOMAIN_TABLES` in `src/test/helpers/db.ts` (before `companies`).

## 3. Rules

### 3.1 Aliases
- An alias may not equal (case-insensitive, trimmed) any company name of the org nor another alias of the org.
- **Rename** (existing 409 `COMPANY_NAME_TAKEN`): also refused when the new name equals an alias of **another** company. Renaming a company to **its own** alias is allowed and removes that alias.
- **Inbox conversion**: the company lookup used by `CommercialInquiryService.resolve` (today `CompaniesRepository.listByName`, exact name) returns companies whose name matches exactly **or** that have an alias matching `lower(trim(guess))`, deduplicated by company id. More than one company → existing `AmbiguousPartyGuessError` ("selecione a correta").

### 3.2 Merge company (duplicate → stays)
1. Lock both companies `FOR UPDATE` in ascending id order; both must exist in the org (`CompanyNotFoundError` otherwise); duplicate ≠ stays (`MergeSameRecordError`).
2. Re-point `brands.company_id`, `contacts.company_id`, `leads.company_id`, `opportunities.company_id` from duplicate to stays (each `UPDATE … WHERE organization_id = :org AND company_id = :duplicate`).
3. Move the duplicate's aliases to stays (skip an alias whose normalized name equals stays' name); add the duplicate's name as an alias unless it equals stays' name (normalized) or is already an alias.
4. Delete the duplicate.
5. Append domain event `company.merged` with payload `{ duplicateId, duplicateName, staysId, moved: { brandIds, contactIds, leadIds, opportunityIds }, aliasesAdded: string[] }`.

### 3.3 Merge contact (duplicate → stays)
1. Lock both contacts in id order; existence/org/same-record checks as above (`ContactNotFoundError`, `MergeSameRecordError`).
2. Re-point `leads.contact_id` from duplicate to stays.
3. Fill stays' empty `email`, `phone`, `instagram_handle`, `company_id` from the duplicate (never overwrite a filled value; `full_name` stays).
4. Delete the duplicate.
5. Append `contact.merged` with `{ duplicateId, duplicateName, staysId, moved: { leadIds }, filledFields: string[] }`.

### 3.4 Concurrency
Locks in id order prevent deadlocks between merges of the same pair; a crossed merge (A→B and B→A) makes the second one find its duplicate deleted → 404. Postgres 40P01 → 409.

## 4. API

All: session (401) → `isUuid(id)` (404) → `canManageOrganization` (403) → zod (400 `{ errors }`). Errors mapped in `src/app/api/crm-errors.ts`.

- `GET /api/companies/[id]/merge-preview?into=<uuid>` → `{ duplicate: { id, name }, stays: { id, name }, result: { name }, impact: { brands, contacts, leads, opportunities }, aliasToAdd: string | null, aliasesMoved: number }`.
- `POST /api/companies/[id]/merge` body `{ into }` → the company that stayed.
- `GET /api/contacts/[id]/merge-preview?into=<uuid>` → `{ duplicate, stays, result: { fullName, email, phone, instagramHandle, company: { id, name } | null }, filledFromDuplicate: string[], impact: { leads } }`.
- `POST /api/contacts/[id]/merge` body `{ into }` → the contact that stayed.
- `DELETE /api/companies/[id]/aliases/[aliasId]` → 204.
- `GET /api/companies/[id]` gains `aliases: Array<{ id, name }>`.

| Error | HTTP | Message |
|---|---|---|
| `CompanyNotFoundError` / `ContactNotFoundError` (record or `into`) | 404 | "Empresa não encontrada." / "Contato não encontrado." |
| `MergeSameRecordError` | 422 `SAME_RECORD` | "Escolha outra empresa." / "Escolha outro contato." |
| `CompanyNameTakenError` (incl. alias) | 409 `COMPANY_NAME_TAKEN` | "Já existe uma empresa com esse nome." |
| `CompanyAliasNotFoundError` | 404 | "Apelido não encontrado." |
| `into` missing/invalid | 400 | "Escolha a empresa que fica." / "Escolha o contato que fica." |
| 40P01 | 409 | `DEADLOCK_MESSAGE` |

## 5. UI

Lucide icons only, no emoji/symbol glyphs; Portuguese copy; no content overflowing containers at 320–1920px.

- **Company detail**: "Mesclar em…" button (icon `Merge`) next to "Editar". New **Apelidos** block (only when there are aliases): each alias with a remove button (icon `X`, aria-label "Remover apelido {nome}"), short confirmation, toast "Apelido removido."; helper text "Nomes que a IA do Inbox reconhece como esta empresa."
- **Merge company dialog**: "Mesclar **{duplicado}** em:" + combobox of the org's other companies → preview: "Fica: **{nome}**", "Vai mover: N brands · N contatos · N oportunidades", "'{duplicado}' passa a ser apelido de '{fica}'", "N apelidos também serão movidos" (when > 0) → warning with icon `TriangleAlert`: "Esta ação não pode ser desfeita. **{duplicado}** será excluída." → "Cancelar" / "Mesclar" (destructive, disabled until the preview loads) → toast "Empresas mescladas.", navigate to `/companies/{fica}`, invalidate CRM queries and inbox option keys.
- **Contact detail / merge contact dialog**: same pattern; combobox shows "{nome} ({empresa})"; preview lists final fields with "(do duplicado)" next to the ones filled from the duplicate, "Vai mover: N leads"; toast "Contatos mesclados."; navigate to `/contacts/{fica}`.
- Dialog errors: 422 under the combobox; 404/409 at the top; preview failure → "Não foi possível carregar a prévia" + "Tentar novamente".

## 6. Tests

Vitest against the real test Postgres.
- **Service — company merge**: every reference moved; duplicate deleted; alias created (not when equal to stays' name); duplicate's aliases moved; event payload; same record → `MergeSameRecordError`; other org's id → not found; other org's rows untouched.
- **Service — contact merge**: leads moved; blanks filled, filled values kept; duplicate deleted; event; error cases.
- **Preview**: impact equals what the merge actually moves; preview writes nothing.
- **Atomicity**: a forced failure mid-transaction leaves no partial change.
- **Aliases**: conversion finds a company by alias; name of one + alias of another → ambiguity; rename refused for another company's alias; rename to own alias allowed and alias removed; unique index; RLS policy test for `company_aliases` (pattern of `src/db/rls-*.test.ts`).
- **Routes**: 401, 403, 404 (incl. malformed `into`), 400, 422, success; new routes in `write-guard` and `id-guard`.
- **Components/pages**: merge dialogs (preview, warning, disabled button, 422 under combobox, redirect), aliases block + removal, contact "(do duplicado)", no glyphs.
- **Manual browser check**: merge two companies and two contacts; see the alias; post an inbox message using the alias and confirm it lands on the right company; layout 320–1920px.

## 7. Out of scope
Brand merge; undo; automatic duplicate suggestions; merging more than two records at once; bulk selection on the lists.
